# Ask53 v0.1.0

First release of Ask53: a small Go service for asking concise AI questions through
direct DNS TXT queries.

## Included

- Configurable OpenAI-compatible Chat Completions integration with strict answer
  size and token limits.
- Bounded caching, identical-request coalescing, rate limits, a durable daily
  attempt budget, and provider failure suppression/circuit breaking.
- UDP and TCP DNS handling; Internet-facing UDP requests require TCP fallback
  before AI work or answer delivery.
- Graceful shutdown, private health/statistics endpoints, a deterministic local
  provider, and systemd/container deployment examples.
- Static Linux and macOS binaries for amd64 and arm64, MIT licensing, dependency
  notices, and SHA-256 checksums.

## Install

Download the archive for your OS/architecture and `SHA256SUMS` from this release.
For Linux amd64:

```sh
sha256sum --ignore-missing -c SHA256SUMS
tar -xzf ask53-v0.1.0-linux-amd64.tar.gz
cd ask53-v0.1.0-linux-amd64
./ask53 -version
```

On macOS, use the appropriate `darwin` archive and
`shasum -a 256 --ignore-missing -c SHA256SUMS` before extraction. These checks
detect damaged downloads; obtain the manifest from the same trusted release.

Read the bundled README before configuring a provider. Defaults bind to loopback.
For local trials, clone the repository and run `make mock` with the bundled local
configuration; the mock provider is not included in binary archives.

## Deployment and limitations

This is a direct-query application, not a recursive resolver or an authoritative
zone server. Public deployments require both TCP and UDP port 53, an appropriate
source allowlist/firewall, and retained budget state. DNS traffic is plaintext;
TCP verifies reachability, not identity. AI output may be inaccurate.

The daily budget limits attempts, not monetary cost. Set provider-side spending
limits and select a model/token cap suitable for short answers. Remote provider
compatibility and latency depend on the selected provider.

Automated race, protocol, provider-failure, caching, concurrency, fuzz, and process
restart tests use fake providers. Live paid providers, Docker execution, and
systemd installation have not been validated locally. See the bundled
`TESTING.md` and README for the verification record and deployment steps.

This is an initial 0.x release; configuration and interfaces may change in future
versions. Keep quota state through upgrades and review release notes first.
